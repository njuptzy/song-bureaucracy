# 宋代官制辞典条目结构化提取 Prompt

你负责把《宋代官制辞典》条目提取为结构化数据，**单阶段直接写入 SQLite**。当前流程
没有中间事实表或中间提取阶段；读取原文后，直接判断哪些内容应写入 Entities、Timepoints、
Relationships、Citations 和 BuildRecords。事实范围、实体边界、时间点含义、关系含义
以及引用处理规则，以原始 `agent_v0303/prompt_input2facts.py` 和
`agent_v0303/prompt_facts2data.py` 的**最终落库含义**为准，但不复刻其两阶段执行流程。
新增的 BuildRecords、逐行 quotation 和事务要求只是追溯增强，不改变“什么应当入库”。
目标：**数据质量必须高于 8–10 编组（v0620-regen-test）**。

## 输入

- 辞典库：`data/database/song_bureaucracy_dictionary_ch<编组>.db`，表 `chapter<编组>`（编组：2t4 / 5t7 / 11t12）。每行：`(id, title, catalog, page, text, fields)`；`fields` 是属性 dict 的 JSON（职源/职掌/官品/编制/简称等）。
- 结果库：`data/database/song_bureaucracy_entries_ch<编组>.db`（四表 + BuildRecords，已建好空表）。
- 标注系统实时只读挂载同一结果库（8644/8645/8646 端口），每条写完刷新页面即可审查。

## 数据模型（严格遵守）

### 四表

- **Entities**：静态实体（`title`、`type`：`机构` 或 `官职`）。只有 `title` **和**
  `type` 都完全一致才默认复用（先查后建）；包含关系、前后缀相似、简称相似都不等于
  同一实体。仅当同名同类型确为不同实体时才允许重复新建，并在 BuildRecords 说明。
- **Timepoints**：实体时间线节点（`entity_id`、`time`、`event`、`prev_id`/`succ_id`、
  `attr_category`、`attr_officer_type`、`attr_grade`）。时间点表示制度状态或变化，按
  原文保留时间文本。prev/succ 必须按历史先后连接并保持互反，不得仅按提取顺序接到链尾。
  新实体已有占位节点时，首个真实时间点应复用并清除“占位”；有真实时间信息后不留
  `time="未知", event="占位"` 的残留节点。
- **Relationships**：连接**时间点**不是实体。方向约定：`上下级机构` = 上级→下级；`编制隶属` = 机构→官职（可带 `staff_quota`/`staff_type`）；`前后演变` = 来源→后继；`统称与实例` = 统称→实例。
- 原文同时涉及两个或更多机构/官职并描述它们之间的制度联系时，必须判断是否应写
  Relationships，不能只把关系文字分别塞进一侧 event。关系两端必须使用与该关系事实
  时间相符的真实时间点；无时间关系才按下文规则连接双方首个时间点。`staff_quota` 只有
  原文明示整数员额时才填写，不能把“设某官”推断成 1，也不能把“无定员/若干”硬转整数。
- **`统称与实例`**：统称 → 实例，用于原文明确表达的统称及其构成实例（如
  “三相”→其所指各相、“九寺五监”→各寺监）。不得把简称、别称或同一正式实体的
  另一称呼当作实例。原文只说某官职“为宰相”时，先忠实判断这项制度事实；只有原文
  明确把二者表达为统称及实例，才建 `统称与实例`，否则不擅自把职任说明改写为该关系。
- **Citations**：挂在 Timepoints 或 Relationships 上（`target_table`、`target_id`、`citation`、`quotation`、`note`、`conflict_flag`）。新证据用追加，不静默覆盖冲突。
- **`前后演变`的用法**：任职形态的改名、改置、复置、终结都用前后演变，两端时间点必须是同一制度变化的两端（来源的**终结/改名节点** → 后继的**新置节点**），如 同平章事（元丰五年罢）→ 仆射兼侍郎（元丰五年四月定）、太宰兼门下侍郎（靖康改回）→ 尚书左仆射（靖康复置）。缺了任一端节点就先补建，不允许悬空挂接。
- **全文仍须扫描简称、别称段落，但当前四表不存别称关系**：不能因为字段名是”简称”
  或”别称”就跳过整段，因为同段可能还包含设立、改名、任职、品级、编制、职掌等可落库
  的制度事实；但纯粹的”A 又称 B””A 简称 B”（无时间、无沿革、无制度事实）不落库，
  不为简称、别称另建实体，也不建立别称关系，更不能改写成”统称与实例”。
  **不能因词条标题是别称组就整条跳过**——别称正文中的时间、沿革、任职配置等可由
  四表表达的制度事实，必须提取到辞典采纳的正式实体上。只有经全文本扫描确认**没有任何
  带时间或沿革的制度事实**的条目，才在批次报告中记录”无四表可表达的制度事实”，不得
  伪造四表行或悬空 BuildRecords。

### BuildRecords（每条四表数据必写）

`target_table / target_id / source_entry / source_page / decision / created_at`。`decision`
必须说明**为什么建、依据原文哪句话**，与四表写入同事务。每次 INSERT 必须写；
若本条处理修改了既有记录（包括插入时间点时改动既有节点的 prev/succ），也要为被修改
的目标追加 BuildRecords，说明修改前后及原因。四表当前行覆盖率必须 100%；凡实际
产生或修改四表数据的辞典条目，都必须能由 BuildRecords 或 Citations 追溯。按原始
agent 原意判定为“有内容但当前四表不支持落库”的条目（如只有纯别称说明），在
批次处理报告中记录跳过原因，不伪造四表行或悬空 BuildRecords。v0620 有 1 条本应
产生数据却漏覆盖的辞典条目，是反面教材。

## 引用规范（v0620 教训的主要来源）

0. **每行数据都必须自带原文**：Entities / Timepoints / Relationships 三表均有 `quotation` 列，新建行时必须填入支撑该行数据的辞典原文逐字片段（与 Citations.quotation 同规则）；Citations 本身也有 quotation。写入辅助库 `process/extract/ew.py` 对此强制必填。
1. 每个 Timepoint、每条 Relationship **至少一条引用**。
2. `citation` 格式统一：`《宋代官制辞典》第{page}页"{条目名}"条`，可附带属性名（如 `职源字段`）。
3. `quotation` **逐字照抄**该条目文本（含 OCR 原字，不润色、不"修正"错字），长度以能独立支撑该数据点为宜。标注系统会逐字回匹配辞典库，匹配率必须 100%——引不到的字一个都不能多。
4. 史料相互矛盾：并列多条引用 + `conflict_flag=1` + `note` 说明，**不擅自取舍**。
5. 正文 OCR 错字不擅改；确需说明真实字形（如"王禹倩"应为"王禹偁"）写进 `note`。
   完全相同的目标、出处和 quotation 已存在时不重复追加。
6. **辞典出处与辞典所引史书不得混淆**：即使辞典正文内部引用《长编》《宋会要》等，
   `citation` 仍写该段文字实际所在的《宋代官制辞典》页码、词条和字段，不把辞典内部
   所引史书冒充为本数据库的直接出处。
7. **当前主条目直接描述其他实体的事实仍要提取**；其 `citation` 写当前主条目。
   同一个既有数据点后来又被另一个主条目直接证明时，可以追加该另一条目的引用，每条
   quotation 都必须在各自实际出处条目中逐字匹配。
8. **“见/参某条”的查询边界与提取范围沿用原始 agent**：只有当前已知词条出现明确的
   “见/详见/参某条”等跳转指引，且该条目尚未加载时，才补读被指条目；普通提到其他
   机构或官职时禁止为了背景知识扩查。完成补读后，对“当前已知的全部辞典词条”依次
   提取可落库的制度事实，包括被明确跳转加载的条目；每条数据的 `citation`、quotation 和
   BuildRecords.source_entry 必须写它实际所在的辞典条目，不得全部冒记在最初主条目
   名下。相同事实后来重复遇到时复用已有行并追加新的实际出处引用，不重复造数据。

## 完整性与保守性

- **全文本细粒度扫描**：不能根据“基本介绍”“简称”“职源”等字段名判断内容价值；
  每个字段中的制度事实同等处理，引文中的隐性制度事实也不能遗漏。
- **时间点宁全勿缺**：原文中每一个带时间或时期的**制度性事实**都必须有对应时间点——置 / 废 / 改名（含避讳改名）/ 迁址 / 并省 / 员额、官品、编制、馆职等配置变化，一个都不能漏。时段表述（"宋前期""元祐初"）照原文作 `time`。链中插入时按历史位置维护 prev/succ 互反；同一实体已有相同时间点时，按原始 agent 规则优先复用该时间点并更新属性、关系或追加引用，不得仅因 event 措辞不同就重复造节点；同一时刻确有彼此独立、无法合并的状态变化时才分建，并在 BuildRecords 说明。
- **不能仅因原文位于“简称/引文”字段或出现人物除授就排除**：若“某年某月某人拜某官”
  实际证明某官职的设置、任职形态或制度变化，仍须提取相应机构/官职事实，人物本身不建
  实体。只有纯粹举例、不能形成独立制度事实的人名除授，以及当前四表无法表达的官名词源，
  才不建时间点。
- **起止型表述**（"X至Y宰相名""政和二年五月至宣和二年六月"）：建起、止两个时间点，同一原文可作两端的 quotation。
- **`前后演变`关系两端必须各自有对应时间点**（v0620 曾缺改名时间点，事后靠脚本补救——本轮不允许出现）。
- **无时间事实沿用原始 agent 的最终落库含义**：不能因缺少时间而漏读；其时间按以下
  优先级确定，**不得默认"未知"**：①出处上下文能确定时期的（如整段在讲宋前期、
  元丰新制），**用该时期作 time**，quotation 照常引出处原文；②确实无法确定时期的，
  把该属性或关系更新或连接到相关实体的首个真实时间点，并挂上原文引用；③前两者都
  不行时，才可使用其 `time="未知", event="占位"` 的首个承载节点，且一旦获得更准的
  时间信息就必须替换该节点。若该属性或关系不被当前四表涵盖
  （典型如纯别称关系、没有对应字段的自由文本属性），则按原始 agent 规则跳过落库，
  不把它硬塞进 event，也不编造新字段或关系。
- 原文没有的，不推断、不补常识、不用背景知识填时间。
- 统称类条目（如"三省"、"九寺五监"）：建统称实体 + `统称与实例` 关系到各实例；实例实体若该条目无据但辞典其他条目有，按同名复用处理。
- **对象只能是宋代官制中的机构或官职**：人物、地名、书名、兵种、军额类别、普通
  人群、泛称和一般名词都不能建实体；只有原文明确把某名称作为官署或正式官职时例外。
- placeholder 条目（`fields.__status__` 有标记、text 为空）不得直接提取，也不得为它
  伪造四表行或悬空 BuildRecords。按 `page` 回原 MinerU OCR 定位正文，并先修复切分、
  重建辞典库；确实无法恢复时在批次处理报告中标记未处理，不把处理状态冒充为史实数据。
- **切分/目录缺陷不在提取层迁就**：发现条目文本残缺、内容错置（如正文换行被拆成伪条目、目录折行拆断长条目名），先在 `split_chapters_2t4.py` 加修复（目录修正清单 / joins 粘连修补，均带原因日志）→ 重跑切分 → 重建辞典库 → 再提取。提取层只面对修好的辞典库。

## 验收标准（每条提交前自查）

1. 标注系统的**硬错误为 0**（引用可解析、条目找得到、无断链、无不合理占位残留、
   无悬空、关系有引用）；合法的 `conflict_flag=1` 是待人工审查警告，不要求消除。
2. 严格逐字检查所有四表 quotation 与 Citations.quotation；不能用标点归一化或 partial
   匹配冒充 100% 逐字匹配。
3. BuildRecords 对全部当前四表行覆盖率 100%，且不存在指向已删除目标的悬空记录；
   链指针更新等既有行修改也有追加审计。
4. 无孤儿数据：每个时间点有所属实体、每条关系两端时间点存在、每条引用指向存在。
5. 人工抽查事实范围：没有遗漏带时间制度事实，也没有把纯别称、人物、地名、兵种、
   泛称误写成实体；显式跳转加载的邻条事实没有遗漏，且每条引用归属实际出处。
6. 批次处理报告覆盖全部待处理辞典条目；没有落库记录的条目必须注明是空 placeholder、
   当前四表不支持的纯别称等事实，还是实际失败，三者不得混淆。

## 流程

1. 先提取**本编组前 10 条**，提交用户在标注系统审查，确认风格与质量标准后再放量。
2. 逐条处理：完整扫描当前已知的全部词条各字段 → 判断每段内容能否由当前四表表达 →
   对可表达的制度事实直接建/复用实体 → 建时间链 → 建关系 →
   挂引用 → 写 BuildRecords。每个实际出处条目的写入使用该条目的 source_entry/page；
   同一轮加载多个词条时仍应按实际出处划分事务或保存点，避免一个条目的失败污染其他条目。
3. 跨条目复用实体时，新增时间点/关系/引用照旧写 BuildRecords（source_entry 写当前条目）。
4. 只有当前已知全部词条都已逐段扫描，可表达的制度事实已经直接落库，不可表达或无须
   落库的内容已按规则跳过并在必要时记入批次处理报告，而且没有写入错误、未解决歧义
   或遗漏段落时，该轮条目才算完成。

## 禁止事项

- 禁止手工改写 `text`/`fields` 原文（润色、补字、"修正"错字）；切分缺陷只能走切分管线修复后重建辞典库（见"完整性与保守性"末条）。
- 禁止用 8–10 编结果库（v0620 等）的数据直接复制——条目不同、页码体系不同，一律从本编组辞典库重新提取。
- 禁止为凑完整而推断原文没有的时间、关系、编制数字。
- 禁止把纯简称、别称、过称、异称或称谓组建成独立实体或“统称与实例”关系；但仍要
  阅读这些段落，不能因此漏掉同段中的其他制度事实。
- 禁止只因正文提到某机构/官职就扩查邻条；只有明确跳转指引才补读。显式跳转加载后的
  邻条属于当前已知辞典信息，须按原始 agent 语义提取，但引用与 BuildRecords 必须归属
  邻条自身。
