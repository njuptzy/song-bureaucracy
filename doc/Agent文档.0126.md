# 官制提取代理工作流程

在上一版本 0120 的基础上进行修改，主要涉及
  * 始置罢置事件更新
  * 强调扩展更新条目到所有相关的条目
  * 插入时间点的逻辑更新
  * 溯源引用问题
  * 代理流程拆分

## 目标

Agent 读取《辞典》条目数据（原始数据），并从中还原出职官条目数据，以及条目之间的关系信息。
期待 Agent 能够解决（包括但不限于）
  * 涉及到《辞典》条目交叉索引的问题，通过主动获取额外的原始条目信息解决
  * 数据中不规范的表达问题，通过上下文，以及查询条目名称解决
  * 根据新增信息，合并或拆分职官条目信息，通过数据更新接口完成

## 基本流程框架

  - 【本地】初始提供《辞典》中的若干条目原始数据
  - 根据需要的职官条目信息（目标数据结构）从原始数据中总结“知识”
  - 查询必要的原始数据以及已有的条目信息
  - 【本地】查询并返回结果
  - 根据结果，优化总结出来的“知识”，并与已有的条目信息合并
  - 产生条目信息更新指令
  - 【本地】执行指令

Agent 需要在大框架下工作，同时应对突发情况，产生对应的策略；
例如，查询必要的资料并优化合并“知识”，可能涉及到多轮迭代；
本地执行的查询或更新指令等工具调用，涉及到反馈；如果包含报错，需要调整指令；

  * 职官条目数据，即最终的输出结果；

### 职官条目数据库

机构条目和官职条目合并在同一个表内；
《辞典》中的一个条目 title-page 可以对应于此表中的多个条目，他们具有相同的 title-page 元信息，但是有不同的始置-罢置时间与事件：根据时间段拆分条目信息，分别有独立的属性记录；
自然索引自增，被拆分的条目会创建新的条目（两个）且原条目会被移除；

元信息
  * 使用自然索引
  * title 条目名称
  * catalog 条目所在目录
  * page 条目所在页码
通用待补充属性
  * type 条目属性分类："机构" 或 "官职"
  * subtype 原文中对于类别的描述，如 "军职名" "官司名" "官名" 等
  * bgn_time 条目覆盖的时间区域起点
  * end_time 条目覆盖的时间区域终点
  * bgn_event 起点时间事件
  * end_event 终止时间事件
  * time_index 切片时间段序号，自动维护，用于排序同一个条目的多个时间段
机构条目待补充属性
  * superiors 上级机构，可能存在多个上级
  * subordinates 下级机构，可能存在多个下级
  * staffing 编制信息，包括编制名称，类别和数量
职官条目待补充属性
  * department 隶属机构
  * grade 品级

官制数据条目（暴露给API）
  - title, catalog, page 对应于《辞典》的条目名称，目录结构以及页码信息
  - type 条目属性分类，"机构" 或 "官职"
  - subtype 更加细致的条目类别，如 "军职名" "官司名" "官名" 等
  - bgn_time, end_time, bgn_event, end_event 该条目覆盖的时间区域起点与终点，以及相应发生的事件
    - 初始时每个条目设有默认的始置事件(bgn_time="-INF", bgn_event="始置")与罢置事件(end_time="INF", end_event="罢置")，分别对应于条目最初设立与最后废除的事件，但是对应的时间描述未知，设为 -INF 和 INF 占位；当确定了相关时间文本后，应当对对应的时间和事件属性进行更新替换；
    - 使用字符串记录时间，可以是标准的年月日格式，也可以是包含年号，季节等相对模糊的叙述；
  - superiors, subordinates “机构”条目的上下级机构，是一个列表，可以包含多个上下级机构
    - 列表中每个元素是一个字符串，代表对应的机构
  - staffing “机构”条目的人员编制，是一个列表
    - 列表中每个元素是一个三元组列表，包含职位名称(str)，类别(str)以及编制数量(num)
  - department “职官”条目所隶属的机构
    - 是一个字符串，代表隶属的机构
  - grade “职官”条目的官职品级，用一段文本描述品级，或品级的范围

## 数据库接口（工具API）

查询数据库操作：
  * 获取《辞典》某条目数据
  * 获取官制数据库某条目数据

更新官制条目数据库的操作：
  * 更新某个属性值，直接修改或覆盖
  * 更新列表中的值，追加更新或删除
  * 插入一个重要时间点，用于拆分条目

通过信息查询工具从《辞典》数据表和官制条目数据表中获取信息；通过《辞典》中给出的名称(title)和所在页码(page)作为索引；
1. 查询《辞典》数据
  * 工具名称：search_dictionary
  * 调用方式：search_dictionary(title, page) 通过条目名称和所在辞典页码唯一确定条目
  * 工具说明：当《辞典》中包含的其他条目对于当前的信息分析与提取至关重要，且并未被包含在输入中时，通过此工具查询《辞典》中对应条目的原始信息，作为输入的补充；
2. 查询已有官制条目数据
  * 工具名称：check_existing_entry
  * 调用方式：check_existing_entry(title, page) 通过条目名称和所在辞典页码唯一确定条目
  * 工具说明：查询官职数据表中已有的条目信息；任何对于官制数据表的更改，都需要先确认现有的相应条目信息，进而决策修改操作；查询会返回一个数据列表，包含指定的条目的所有时间段的数据项信息；

通过写入工具更新修改官制条目数据表；通过名称(title)，页码(page)，以及起始与终止时间(bgn_time, end_time)唯一索引指定条目指定时间段对应的数据项；
1. 更新官制条目的指定属性值
  * 工具名称：update_attr
  * 调用方式：update_attr(title, page, bgn_time, end_time, attr_key, attr_value)
  * 工具说明：更新一个条目的指定属性，会直接覆盖原值；
2. 向官制条目的指定列表属性中插入值
  * 工具名称：append_list
  * 调用方式：append_list(title, page, bgn_time, end_time, attr_key, attr_value, index=None)
  * 工具说明：向条目中的列表类型属性插入一个新的值；如果不指定 index 则默认插入到列表末尾；
3. 更新官制条目的指定列表属性中的指定值
  * 工具名称：update_list
  * update_list(title, page, bgn_time, end_time, attr_key, attr_value, index)
  * 工具说明：修改条目中的列表类型属性中的指定值；会直接覆盖原值，应当谨慎使用；
4. 删除官制条目的指定列表属性中的指定值
  * 工具名称：remove_list
  * 调用方式：remove_list(title, page, bgn_time, end_time, attr_key, attr_value, index)
  * 工具说明：删除条目中的列表类型属性中的指定值，应当谨慎使用；其中 attr_value 为保险，要求与原值一致，防止误删；
5. 通过插入时间点的方式，拆分官制条目
  * 工具名称：insert_time_point
  * 调用方式：insert_time_point(title, page, bgn_time, end_time, time_point, event)
  * 工具说明：当发现了官制条目的新的重要时间点时，需要将其扩展，额外拆分出一个条目，分别覆盖每一段时间段；确保新时间点出现在当前 metadata 选定的条目所覆盖的时间范围的起止时间点之间；该工具会自动将该条目拆分为两个新的条目，旧条目将被移除；拆分后的新条目会自动继承旧条目的其他属性；
6. 通过追加时间点的方式，拆分官制条目
  * 工具名称：expend_time_point
  * 调用方式：expend_time_point(title, page, bgn_time, end_time, exp_type, time_point, event)
  * 工具说明：当新的重要时间点在当前条目所覆盖的时间段之外时，通过扩展最早的时间点或最晚的时间点，扩展条目覆盖的时间范围；选取最早的时间段对应的条目，在其开始时间前添加新时间点；或选取最晚的时间段对应的条目，在其结束时间后添加新的时间点；其中 exp_type 为保险，确保选取最早时间段时向前添加，exp_type="before"；选取最晚时间段时向后添加，exp_type="after"；这个操作不会影响原有的时间段条目，而是在现有时间段之前或之后增加新的时间段；

注意事项
1. 所有写入操作必须基于 check_existing_entry 获取的准确元数据。
2. 在连续的多步写入操作中，需要注意由于先前操作导致的数据项元数据变化，在后续操作中准确填入更新后的元数据，避免操作失效；例如连续更新 bgn_time, end_time 时，先更新了 bgn_time 后，元数据发生变化，再更新 end_time 就需要采用刚刚更新的 bgn_time 作为元数据索引；
3. 初始条目会使用 -INF 和 INF 作为占位符，分别记录条目的 bgn_time 和 end_time；同时默认的首个事件与最后事件分别为 "始置" 与 "罢置"；后续需要根据实际数据信息，使用 update 工具替换占位符，填写明确的时间信息；部分情况下首尾事件并非始置与罢置，同样使用 update 更新；
4. 使用 update 更新或使用 new_time_point 拆分了时间或事件数据后（bgn_time, end_time, bgn_event, end_event），后续紧跟着的属性操作应当使用更新后的元数据；原本的元数据指向的条目已经被移除了；

## 代理输出格式

使用 CoT 思维链的格式进行输出，采用 JSON 格式组织信息，请仅输出当前轮次的逻辑推演结果，格式如下：
{
  "thought": "对当前信息的分析及下一步规划",
  "action": "Tasks All Finished" 或 [ {"tool": "...", "parameters": {...}, "reasoning": {...} } ],
  "observation": "如果是自主生成的结论则填写，否则留空等待系统返回"
}

### Thought
要求以纯字符串的形式输出思考过程，包含对上一轮结果的分析，对之后步骤的规划等内容；

### Action
如果本轮次的行动不需要调用工具等待结果，则应当以字符串形式描述本轮行动的具体要求；

如果本轮次的行动需要调用工具，则以以下方式输出结构化的工具调用指令，为一个 JSON 列表：

[
  {
    "tool": "TOOL_NAME",
    "parameters": {
      "PARAM_NAME": "PARAM_VALUE"
    },
    "reasoning": {
      "citations": [
        {
          "reference": "...",
          "content": "..."
        }
      ],
      "inference": "..."
    }
  }
]

其中，如果调用的工具属于更新数据库的操作，则需要进一步提供更新操作所依赖的原文证据，记录在 reasoning 字段中；如果是查询工具，则不需要该字段；
reasoning 字段中包含
  - citations 引文字段，为一个列表，可以包含一个或多个引用
    - reference 一个格式化字符串记录引文来源
      - 目前，引文的唯一来源为《辞典》条目，约定引文格式为: "《辞典》XX页 XXX条目 XX字段"
    - content 引文的具体内容，包含从上述来源中截取的最短相关段落原文
  - inference 推理字段（可选），当引文内容与结论存在差距，或多个引文不一致等情况，在此字段记录基于上述引用的推理过程和做出结论的理由描述

如果完整的任务已经完成，在 Action 中输出字符串 "Tasks All Finished" 并结束整个流程；

### Observation
  * 若 Action 为工具调用：停止输出，等待系统返回 Observation；Action 允许一次调用多个工具，你应当尽可能将相对独立的工具调用一次性调用，如查询多个条目的信息等。
  * 若 Action 为逻辑结论或中间步骤（如：决定下一步要去搜什么）：Observation 部分应总结该步骤的发现。
  * 若 Action 为 Tasks All Finished：不输出 Observation，直接结束。
